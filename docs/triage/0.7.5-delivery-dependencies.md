Baseline: released v0.7.4, commit `e313d34` plus parent plan commit `9261263`. This branch keeps

## #367 — quiet hours end at the real instant, not a wall-clock count

**Root cause.** `quietUntil` read the local minute correctly but added `(end - now + 1440) % 1440`
wall-clock minutes to the absolute timestamp. Any offset change between `now` and the end shifted
the wake instant by the offset change; New York's 2026-03-08 spring forward made a 01:30 EST defer
wake at 09:00 EDT (13:00Z) instead of 08:00 EDT (12:00Z).

**Fix.** The local end reading is resolved as a zoned instant:

- `packages/core/src/datetime.ts` now owns `zonedParts` and `zonedInstant` (the helper previously
  private to `packages/audience/src/broadcasts.ts`, which now imports them; behavior unchanged).
- `packages/email/src/policy.ts` resolves the end reading on the correct local date, then picks the
  earliest actual instant that reaches it. A fall-back fold has two readings, so the earliest one
  at or after `now` wins. A spring-forward gap has none, so the transition instant is the end. The
  result is still rounded up to a whole minute, so defer/re-check behavior is unchanged.
- Normal windows (`start < end`), overnight windows (`start > end`), the exact start boundary
  (quiet), the exact end boundary (not quiet), and `start === end` (never quiet) keep their old
  meaning. An invalid IANA zone still throws `RangeError`; `checkPolicy` keeps its `validZone`
  fallback to the policy zone. No migration or schema change.

**Regression evidence (packages/email).**

- `packages/email/test/policy.test.ts` — New York 2026-03-08 01:30 EST `22:00–08:00` → `12:00Z`
  (the reported repro); New York 2026-11-01 fall back → `13:00Z`; end inside a fold (earliest
  occurrence, and the second occurrence when `now` is in it); end inside the spring gap → the jump
  (`07:00Z`); Lord Howe's 30-minute spring/fall transitions, including an end inside the 30-minute
  gap; `Asia/Tokyo` as a non-DST control; boundary/invalid-zone/rounding controls.
- `pnpm vitest run --project packages packages/email/test`: 9 files, 65 tests passed.
- `pnpm vitest run --project packages packages/email/test packages/audience/test packages/core/test`:
  14 files, 117 tests passed.
- Typecheck: `core`, `email`, `audience` and `server` pass.

## #406 — the unpatched deepmerge is gone from the production chain

**Live state checked on 2026-11-05 (not the 0.7.0 audit snapshot).**

- `npm view html-to-text`: latest `10.0.1`, published 2026-08-19 (more than two weeks old, so it
  satisfies the repository's dependency-age policy); `engines.node >= 20.19.0`, below the
  repository's `>=22`. `10.0.1` specifically updates `deepmerge-ts` from 7.1.5 to 8.0.1 for its own
  advisory.
- `html-to-text@10.0.1` dependencies: `deepmerge-ts ^8.0.1` (resolved 8.0.2), `htmlparser2 ^10.1.0`,
  `selderee`, `@selderee/plugin-htmlparser2`, `dom-serializer`. No `deepmerge`.
- `deepmerge` still has no release after `4.3.1` (published 2023-03-16), so there is no patched
  version to override to; a `pnpm.overrides` entry or an audit ignore would both be wrong.
- `@types/html-to-text` is still 9.0.4 (types only, no v10 types); the package typecheck confirms
  the used `convert(html, { wordwrap, selectors })` surface still compiles. The stored value is
  still a string.

**Change.** `packages/email/package.json` pins `html-to-text` `10.0.1`; `pnpm-lock.yaml` resolves
`deepmerge-ts@8.0.2` and contains no `deepmerge@*` entry.

**Compatibility and safety.** The renderer passes only a fixed literal options object (`wordwrap:
78`, `selectors` skipping `img` and hiding a same-text link href); the HTML being converted is
parsed, never merged. `packages/email/test/render.test.ts` now pins that surface: image alt text is
skipped, a link whose text equals its href is printed once, and wrapped lines stay at or below 78
columns. The existing `ignoreIncludes: true` sandbox test still passes. No provider account was
contacted and no real send was made.

**Post-change verification.**

- `pnpm --filter @agentic-marketing/email why deepmerge` → empty (no match).
- `pnpm --filter @agentic-marketing/email why deepmerge-ts` → `html-to-text 10.0.1 └── deepmerge-ts 8.0.2`.
- `pnpm audit --prod --json` → no advisory 1243505 / GHSA-gcqx-w48m-w2h4; the remaining report is
  the accepted `uuid` advisory in the excluded `spikes/email-editor` (GHSA-w5hq-g745-h8pq).
- `pnpm audit --prod --audit-level=moderate` → exit 0, "2 moderate (1 ignored)".
- `SECURITY.md` records the resolved advisory, the fixed-input reasoning, and the revisit trigger
  instead of adding an ignore. `apps/server/test/v075-delivery-dependencies.test.ts` guards the pin,
  the absent `deepmerge`, and the SECURITY.md disposition.

**Limits.** `@types/html-to-text` stays at 9.x because no v10 types are published; it is
compile-time only. The test fixture pins our options and representative output, not every HTML
construct. This removal is justified by the fixed internal options object; if an application path
ever passes caller-controlled merge options to `html-to-text`, re-assess before relying on it.
