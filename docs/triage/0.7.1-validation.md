# 0.7.1 validation

Candidate based on v0.7.0 (`391dcba`), verified 2026-11-04. The selected 22 reports and deferred batches are in [the issue plan](0.7-bugfix-plan.md).

- Full workspace typecheck passed (packages, server and web).
- Repository lint passed with existing warnings; `git diff --check` passed.
- Package/frontend tests passed. The combined docs/package/web run had 546 passes, one optional OpenBao skip and one stale generated-catalog failure. After regenerating the catalog, all nine documentation tests passed.
- Nine integration suites passed 140 tests. Review added Unicode/ownership and retention-batch coverage: the three affected suites passed all 29 tests on rerun. The remaining webhook (9), advertising (7) and warehouse (4) suites passed. These cover 162 distinct tests in 12 targeted integration files in the final candidate.
- All 12 version surfaces agree on 0.7.1. The Compose bundle builds with the required upgrade block. Release-note validation was corrected to avoid a SIGPIPE false failure under `pipefail`.
- The existing GitHub CI remains the gate for the full server suite, browser e2e, Docker smoke, Helm validation and dependency review before merging and publishing. Local targeted tests do not substitute for those gates.

Tests used fresh Postgres, ClickHouse, NATS and Valkey containers, separate from the running installation. Transform caches were disabled for integration rechecks. Parallel test processes initially contended over the template database; final integration runs were coordinated to avoid concurrent template setup.

Review corrected an invalid premise in #359: migration 0064 already cascades profile-score erasure. Only expired-score retention was missing. Regression tests preserve the existing cascade and cover an in-flight writer seeing an erased profile. Calibration excludes expired scores consistently before and after bounded cleanup; its outcome window requires a suitably longer prediction TTL for a complete evaluation.

Event-property filtering removes known top-level personal keys and schema-declared PII, not arbitrary personal data hidden in nested/free-text fields. Existing exported rows and raw call inputs are not rewritten. The upgrade notes identify those limits and the required proxy/SDK actions.
