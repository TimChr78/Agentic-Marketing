## Independent review corrections

Current, typed user/anonymous identifier maps take precedence over historical ClickHouse profile ids in campaign and calibration attribution. Immutable pre-merge event rows are therefore credited to the current survivor. Existing >100k server fixtures now include a stale historical profile id, so both callers exercise this path.

The ClickHouse client automatically sends oversized query parameters as multipart bodies. A new wire regression supplies 20,000 profile ids, 20,000 anonymous ids and 20,000 user ids, exceeding the default URI limit. The first run exposed the separate 128 KiB form-field limit; each identity parameter is now byte-bounded below 64 KiB, with OR predicates preserving the full scope. The positive match is in the final user-id chunk. Explicitly empty scopes return no events rather than widening to a workspace read.

Split first-take selection now precedes report-window filtering: a later loop cannot become the first take merely because the report starts later. The server fixture checks this window boundary. Profile exports add `eventsTruncated` and test a full export, a smaller cap, an exact cap, and a zero cap with retained events.

Correction package verification: 109 focused tests and all nine docs tests pass. Events/campaigns/profiles/AI/server typechecks, including the new tests, pass. The first expanded server run passed six cases and failed the large-scope wire case on the form-field limit. The corrected frozen rerun passed all seven cases, including the final-chunk positive match. Final-head CI remains required before merge.
