# 0.7.4 editor validation

Issues: #381, #382, #383, #384. PR #411 starts from released 0.7.3; implementation PRs keep release versions unchanged.

Independent review found no P1 and two small P2 defects. Both are corrected before merge: pagination cursors validate real calendar/time fields before PostgreSQL casts, and explicit Discard remounts editor-local buffers so invalid JSON disappears with the discarded draft. Cursor output is now explicit full-precision UTC text, independent of PostgreSQL DateStyle. Existing valid offset cursors remain accepted.

Earlier parent corrections invalidate save tickets across A → B → A navigation, clear JSON errors on real document switches, and seed a 201-row pagination boundary inside one JavaScript millisecond.

Validation after review corrections:

- Web and artifact package tests: 107 passed; 11 existing built-bundle checks skipped because build output is absent. The new mounted Discard regression runs and passes.
- Docs/catalog tests: 9 passed.
- Web, artifacts and server typechecks: passed.
- Biome: no errors; one existing explicit-any warning in the editor interface.
- Coordinated server pagination regression: 2 passed, including microsecond boundaries and invalid-calendar HTTP 400 responses.

The list loader retains its 20,000-row safety cap. The main list reports incomplete results; pickers do not yet expose that cap and can make up to 100 sequential requests. Independent review identified these as P3 limits, along with pre-existing editor stale-closure cases; they are outside the four selected fixes. No live deployment or browser session was used for validation.
