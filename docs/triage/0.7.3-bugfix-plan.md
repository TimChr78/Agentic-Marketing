## Hosted integration corrections

The first hosted integration run passed 14 cases and failed four new cases. Three exposed a pre-existing missing DELETE grant on `agents` (the app role could never complete `agents.deleteHosted`); migration `0071_hosted_agent_delete.sql` supplies that grant while existing workspace FORCE RLS and human-only workspace-admin command authorization remain in force. Deletion now locks the hosted row before checking its claim, and late completion keeps an existing hosted row under a key-share lock through run-history insertion. The fourth failure used PostgreSQL infinity as a fixture date that the command output could not serialize; the fixture now uses a finite date 100 years ahead. The corrected integration group passes all 18 tests across the new lifecycle suite and existing hosted-agent suite.

## Hosted independent review

The first hosted review found no P1 blocker and two P2 corrections: delete vs rename lock order, and skipped event attempts accidentally consuming event cap/gap limits after their trigger labels were corrected. Deletion now takes the agent row before its hosted row, matching rename/update order. Both the scheduler candidate SQL and event-origin admission exclude skipped attempts from gap/cap accounting. Added deterministic concurrent rename/deletion and skip-admission regressions; the hosted suites pass all 20 cases. Claim ownership still fences late completion, and docs now distinguish one live claim from a slow stale run finishing alongside its successor.

## Budget integration checkpoint

The budget task returned atomic reservation/usage settlement, fallback usage persistence, per-step copilot admission and cancellation accounting. Parent integration strengthened the initial hold deadline before provider I/O, through the end of the following UTC month, so a complete database outage cannot leave only a five-minute hold and a call crossing month-end remains covered. Settlement never shortens this original deadline. Successful calls remove holds promptly; interrupted/unreconciled calls can conservatively reduce availability until expiry. Pre-call input token counts remain estimates, and the upgrade notes explicitly disclose possible final-step overshoot. Budget integration and full workspace checks are running; independent review must verify these limits and failure paths.
