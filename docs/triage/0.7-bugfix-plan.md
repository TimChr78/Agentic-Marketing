# 0.7.x bug validation and release plan

Baseline: `391dcba` (v0.7.0). Inventory captured 2026-11-04: 105 open issues; 60 reports in #347–406 reviewed: 59 confirmed and #359 partially confirmed (retention only), with impact corrections recorded in the linked evidence. The remaining 45 are feature, design, documentation or maintenance requests outside this bug-fix selection.

Priority reflects exposure and data loss, not the original labels. P0: immediate privacy/availability exposure; P1: broken consent, erasure, authorization or core reliability; P2: bounded correctness/concurrency defect; P3: documentation or low-risk dependency disposition. These are engineering priorities, not claims that exploitation occurred.

## Release selection

0.7.1 selects HTTP request limits and proxy trust; decision-model privacy, validation and score consistency; score expiry and erasure regression coverage; hosted-memory ownership/caps; event-property hygiene and ad consent; SDK logout/withdrawal/beacon reliability; queued webhook consent revalidation. Fixes require focused regression coverage and the existing release CI gates before publication.

Later 0.7.x batches cover remaining merge/erasure and warehouse correctness first, followed by audience sync, hosted/budget lifecycle, operational reliability, deployment configuration and editor/measurement correctness. API-compatible correctness fixes do not require 0.8.0. No issue is closed solely on static validation.

## Integration correction to #359

Migration `0064_decision_models.sql:30` already declares `FOREIGN KEY (workspace_id, profile_id) REFERENCES profiles (...) ON DELETE CASCADE`. The initial report inferred no foreign key from the Drizzle schema and was wrong about erasure. A database-backed regression proves erasure already cascades. Only missing expired-score retention is confirmed, priority P2. No orphan repair or schema migration is needed. The score writer also handles erasure during an in-flight request gracefully.

## Review follow-ups in 0.7.1

Memory mutations serialize the shared budget and count Unicode code points consistently with PostgreSQL `char_length`. Agent deletion checks the author run belongs to the same agent, with a real run-written-note test. Retention deletes at most 5,000 expired scores per workspace per hourly pass using the existing workspace/expiry index. Calibration excludes expired scores both before and after cleanup; its outcome window requires an appropriately longer score TTL for a complete evaluation. The release-bundle validator now consumes its entire notes pipe to avoid false missing-field errors from SIGPIPE.
