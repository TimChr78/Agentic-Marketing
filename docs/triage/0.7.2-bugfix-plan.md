## Validation approach

Revalidate against the authoritative SQL migrations and runtime paths, not only the Drizzle schema. The 0.7.1 work found that #359's erasure claim was already covered by an SQL foreign key; only its expiry-retention claim was real. For this batch, execute database-backed regressions and the new SQL helpers as the app role, check existing-state repair, and preserve public command/artifact shapes.

Three scoped DeepSeek V4.1 Flash implementations through OpenCode Go cover warehouse, merge and edge behavior. The parent owns bulk-read auditing, audience consent, integration review and release. Server-project test runs are coordinated to avoid concurrent resets of the shared template database. All local services are disposable containers, separate from the running installation.

## Known merge semantics

The newest topic choice wins; an exact timestamp tie resolves to `unsubscribed`. History stays on its original profile and remains reachable through family export and cascading erasure. Static/snapshot lists keep the earliest addition and provenance. No segment-entry/exit events are emitted merely because identities merge. Dynamic memberships remain derived and are recomputed by normal refresh.

Migration repair follows resolvable merge chains up to 20 links; broken or longer chains are not reconstructed. Old signed topic/preference links are resolved to the surviving profile. Topic writes serialize with identity merges and re-resolve inside the write transaction, preventing a concurrent write from recreating a current choice on a tombstone.

## Warehouse and edge review corrections

Incomplete warehouse erasures advance their cursor and create a metadata-only backlog, so subsequent empty exports cannot hide unresolved deletion failures or retain later raw identifiers indefinitely. Administrators inspect `warehouse.erasureBacklog` and acknowledge selected completed manual cleanups with `warehouse.acknowledgeErasures` and a required note. Export runs serialize per destination. No raw deletion keys are captured without a destination; deleting the final destination drops remaining keys. Captured identifiers remain private and are pruned after enabled destinations pass their erasure. Disabled destinations resumed after keys were pruned fail clearly and require downstream cleanup rather than claiming success.

An edge erasure target lookup failure propagates instead of treating an unavailable database as an absent target. Old-target cleanup failures remain visible in the existing `lastError` field even while the new target syncs successfully, as well as in additive stale-target details. Cross-account cleanup uses the current token; lack of access requires manual cleanup of the old namespace.

Edge sync workers serialize per workspace across replicas. Configuration generations fence metadata and outbox acknowledgements; bundle keys are reserved before remote uploads so a concurrent move retains their cleanup. Configuration reads lock the target row, token rotation inherits an omitted API base, and reused namespaces retain their historical write keys for cleanup.
