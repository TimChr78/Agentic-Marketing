## Review corrections

The hosted review found two P2s: lock order during concurrent rename/deletion and skipped event attempts consuming event limits. Both were corrected and covered by deterministic regressions. The follow-up review confirmed these fixes and found no P1 in the selected budget/hosted changes.

The budget review found a journey fallback that only persisted tokens and left the participant waiting for its node timeout. The fallback now records the provider/model and usage and wakes the participant in one transaction, without a score or another provider request. Its forced-failure regression passes.

Integration exposed that the full copilot MCP catalog (136 tools, about 27,500 estimated schema tokens) could exceed a 20,000-token turn before a model call. The final correction advertises core tools plus bounded discovery, estimates only active schemas, and trims complete user turns. Its integration/helper tests pass; independent delta review remains pending.

## Operational limits and publication gates

Decision/copilot reservations are committed before provider I/O through the end of the following UTC month to cover outages and calls crossing month-end. Normal settlement replaces the hold with recorded usage atomically. Unreconciled holds can conservatively reduce provider availability until their deadline; review provider usage/errors before manual reconciliation.

Copilot counts actual completed-step usage but estimates the next input, including history and active tool schemas, before calling a provider. Provider-specific input tokenization can exceed that estimate on the final step. Discovery can add only a bounded number of already-granted tools; an oversized schema is reported rather than advertised. Neither the tool catalog nor command authorization is expanded.

A hosted claim older than 60 minutes is considered abandoned; the old process can still finish alongside its successor, but its completion cannot change successor state. Its own run history and sponsor notification remain auditable.

The PR must remain draft until the independent delta review is resolved. Full GitHub CI on the exact final head gates merge; the release workflow gates publication. Issues close only when their fixes merge, and publication is verified separately.
