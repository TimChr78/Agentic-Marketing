# 0.7.5 public endpoint and hosted scope validation

Issues #364, #379, #380. Baseline: released 0.7.4. The implementation and independent initial review confirmed the hosted granted-only catalogue and shared form bucket fixes; the first reset queue design still exposed account-dependent request work and was replaced.

The public reset route now performs normalization, shared buckets/cooldown, local installation-secret sealing and one durable insert for every valid address. Account lookup, eligibility, tenant keys, verification minting and provider delivery occur only in the worker. The queue uses claim ids, send-time eligibility/token checks, four attempts, payload expiration and terminal pruning. Without a worker it neither sends nor cleans up; docs state that limit. Delivery remains at least once.

## Parent integration

A fresh token which failed publication to the queue remains separately disposable because no other worker can have received it. The takeover regression exercises late `failed` and `no_sender` outcomes, checks one durable sent outcome, and uses the successor's mailed link to reset the password successfully.

The corrected reset-only server gate passes all 23 cases; the other three coordinated suites passed earlier. Server typecheck and Biome pass. Independent redesign review and final CI remain pending; no claim of review approval is made here.

## CodeQL token classification

The first redesign head produced two `js/insufficient-password-hash` alerts naming `createPasswordResetToken` as the password source. This helper returns `randomBytes(24)` encoded as base64url, not a human password. CodeQL's `SensitiveCall` heuristic classifies calls by sensitive-looking callee names ([upstream source](https://github.com/github/codeql/blob/main/javascript/ql/lib/semmle/javascript/security/SensitiveActions.qll)). The helper is now named `mintResetVerification`, with its 192-bit random-token purpose explicit. Better Auth's reset-identifier SHA-256/base64url format, the application's real password hashing, and all CodeQL rules are unchanged. No alert was dismissed or suppressed. Final analysis must confirm the corrected head.

Versions remain 0.7.4. Only unreleased migration 0074 is new and mapped to 0.7.5; released migrations remain untouched.


## Final independent review corrections

The independent redesign review confirms the public request path is account-independent and verifies the parent's claim-fenced token deletion. Its remaining P2 findings are addressed directly:

- Early unknown/changed-account and ineligible-account exits open and revoke an existing retry token under the same claim fence before settling. Revocation errors leave the payload recoverable for retry. New regressions seed a token through a failed sender, then remove the credential, enforce SSO, change the address, or replace its owner, and require the verification row to be gone.
- Valkey failures return a uniform generic 503 before enqueue or reset forwarding. All three request aliases, all three bucket positions, known/unknown addresses, and submission forwarding are covered.
- The worker uses the abortable `node:timers/promises` delay, which releases idle listeners. A deterministic 30-tick regression checks listener counts and clean abort.
- Operations documentation distinguishes the supported 0.7.4→0.7.5 path from disposable development databases which applied an intermediate 0074. Checksum validation stays intact; released migrations stay untouched. The migration comment now accurately describes terminal account-id retention.

The earlier b262690 head passed every CI check including CodeQL, and branch CodeQL alerts were empty. The final correction gate passes all 94 cases across password-reset, hosted-agents, MCP toolset, version and body-limit server suites. Server typecheck, Biome and all nine docs tests pass. Final-head CI remains required before merge.
