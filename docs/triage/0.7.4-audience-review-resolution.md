# 0.7.4 audience review corrections

The [independent review](0.7.4-audience-review-final.md) found two P1 ownership defects. Both are corrected in this delta:

- Meta remote identity is platform + audience id. The connection remains credential provenance, but spend-import account settings never split target locks or ownership. The current-reference builder, stored-target locks and ownership SQL use the same identity.
- Partially shared identifier sets retain their complete ledger/intent coverage and become an explicit orphaned manual-cleanup obligation. A whole-member removal could delete the other owner's valid member, so this case intentionally fails with a visible backlog rather than dropping one hash or silently acknowledging the entire set. Operators must remove the old member and restore valid owners before acknowledging. Entirely shared sets remain covered by another ledger; entirely unshared sets are removed normally. Profile-id equality alone never authorizes discarding different hashes.

P2 corrections:

- Disabled/disconnected/unreadable current connections mark stored rows orphaned, making unresolved counts and backlog entries visible.
- Bounded scheduler selection uses a sorted cursor across ticks, including failures, and wraps when a pass ends. Restarting the scheduler restarts the pass.
- Merge repair immediately restores the eligible survivor with full identifiers, independent of the regular reconciliation cursor's budget.
- Unpublished/deleted cleanup summaries support cleanupAfter/cleanupNext/cleanupTotal instead of silently truncating after 200 sync ids.
- Docs explicitly explain that acknowledging cleanup does not suppress a still-eligible member's future upload or clear an unrelated run failure. Those other errors require a successful retry.

Regression coverage includes different Meta connections/account settings sharing one target lock, settings-only changes with no evacuation, partially shared ledger and ambiguous-intent obligations, disabled backlog visibility, merge restoration with regular reconciliation disabled, real SQL scheduler pagination/wrap, and cleanup summaries beyond 200 sync ids. The new state fixtures require status and use distinct person identifiers.

Checks: pure reconciliation suite 16 passed; docs 9 passed; changed-file Biome and ads/server typechecks passed before the final test-only additions. Final coordinated 30-case server gate, typecheck and delta review remain pending at this checkpoint. No issue closes or merge occurs until those gates pass.

Residual limits from review remain explicit: permanently failing rows can hold their own bounded removal/intent page; unreachable prior destinations can occupy the 50-group cap; large legacy groups incur repeated orphan updates; historical destination provenance cannot be recovered. These obligations stay visible and acknowledgement is never automatic.
