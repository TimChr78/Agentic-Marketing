- Credential redaction now decides three value shapes from the original text, so a value the rules could only see in part is replaced whole: a PEM private-key block (standalone, under a credential key, or after an arrow, with the header at the start of a line and a footer label that matches it; an encrypted block's `Proc-Type`/`DEK-Info` preamble is part of the block), a typographic-quoted value (`token: “short pw”`), and a value after an arrow (`'password' => 'x'`, `apiSecret => secret`). The released rules and passes still run first, on the whole message, and only the value is taken away: an unterminated PEM block is redacted as far as its base64 body reaches, a quoted value ends at its own closing quote, prose with an apostrophe or a mid-line mention keeps its text, and a second pass changes nothing. Text glued to a redaction marker is still removed as it was, because the original text says who wrote the marker, never that what follows is harmless.
