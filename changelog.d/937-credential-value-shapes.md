- Credential redaction now replaces the value in shapes the released rules leave in part, as passes over their output: a JSON array or object under a credential key (`{"token":["shortpw"]}`, `{"secret":{"v":"x"}}`), a short Authorization value (`authToken=Bearer abc`, `password: Basic xyz`), a whole PEM private-key block at the start of a line (standalone or after a credential key), escaped JSON inside a string (`{\"password\":\"x\"}`), URL-encoded pairs (`password%3Dsecret`, `token%22%3A%22abc`, `api%5Fkey=`), a `Pwd`/`Pass` camel ending (`userPwd`, `dbPwd`, `dbPass`), a credential pair nested in another (`SIGNINGKEY=AZUREOPENAIKEY='x'`), and text attached to an existing marker (`token=[redacted]shortpw`). A typographic-quoted value (`token: “short pw”`) and a value after `=>` (`'password' => 'x'`) are left as the released pipeline leaves them: its output no longer shows the opening quote or the arrow, so a safe pass needs the original input. Ordinary JSON, counters such as `"tokens": 1234`, prose with quotes or `=>`, a quoted or mid-line `BEGIN … PRIVATE KEY` mention, and public `BEGIN CERTIFICATE` blocks keep their text, and a second pass still changes nothing.
