- Credential redaction now replaces the value in shapes the released rules leave in part, as passes over their output: a JSON array or object under a credential key (`{"token":["shortpw"]}`, `{"secret":{"v":"x"}}`), a short Authorization value (`authToken=Bearer abc`, `password: Basic xyz`), a typographic-quoted value (`token: “short pw”`, `‘…’`, `«…»`), a quoted value after `=>` (`'password' => 'x'`), a whole PEM private-key block (standalone or after a credential key), escaped JSON inside a string (`{\"password\":\"x\"}`), URL-encoded pairs (`password%3Dsecret`, `token%22%3A%22abc`, `api%5Fkey=`), a `Pwd`/`Pass` camel ending (`userPwd`, `dbPwd`, `dbPass`), a credential pair nested in another (`SIGNINGKEY=AZUREOPENAIKEY='x'`), and text glued to an existing marker (`token=[redacted]shortpw`). A bare value after `=>`, and a typographic value whose remainder has spaces but no closing quote on its line, are left as the released pipeline leaves them. Ordinary JSON, counters such as `"tokens": 1234`, prose with quotes or `=>`, and public `BEGIN CERTIFICATE` blocks keep their text, and a second pass still changes nothing.
