section: Security
issues: [898]
---
- Credential redaction now recognises a key by its last word, split on camelCase/PascalCase boundaries and on `_`, `-` and `.`: `authToken`, `apiSecret`, `oauthToken`, `X-Auth-Token`, `"accessToken"` and a `?apiSecret=` query parameter are redacted like `access_token` already was, while `monkey`, `keyboard`, `author`, `authority`, `tokenizer` and `sessions_count` are left alone. A credential pair nested in another value (`access token: access_token=…`) is still redacted field by field, and a message with nothing to redact is unchanged.
- For the word `key` the rule is narrower, so ordinary camelCase fields keep their text in validation and conflict messages: `key` on its own, a compound reached through `_`, `-` or `.` (as 0.14.20 treated it: `tenant_key`, `x-tenant-key`, `config.key`, `ENTRY_KEY`, `api_key`), and a camelCase/PascalCase compound whose preceding word is a credential qualifier — `api`, `secret`, `private`, `signing`, `access`, `auth`, `session`, `client`, `consumer`, `encryption`, `hmac`, `jwt`, `vault`, the provider names this codebase integrates with (`openai`, `anthropic`, `stripe`, `twilio`, `shopify`, `salesforce`, `postmark`, `fcm`, `apns`, …), and the rest of a fixed list — are credential keys. `entryKey`, `idempotencyKey`, `sortKey`, `primaryKey`, `cacheKey`, `foreignKey`, `keyId` and `Allowed keys` are not, so `config.entryKey: property is required …` reaches the person unchanged, and every input 0.14.20 redacted is still redacted (a committed differential fixture checks it). An ordinary `…Key` field's value is still covered by every other rule, so a provider prefix, a JWT, a URL password or a long bare token there is redacted all the same. A qualifier-free compound a future provider invents (`tenantKey`) is the accepted cost; a test derives the provider ids from the adapter, connector and model registries and fails when one has no qualifier.
- The scanner matches JavaScript's `\s` again, so a non-breaking space or U+2028 around the separator redacts like an ASCII space did in 0.14.20, and it recognises `=>` as a separator, paired Unicode quotes (`“…”`, `‘…’`), and a marker that is only kept when the value really ends there: `token=[redacted]shortpw` is redacted instead of left readable.
- The value of a credential key is taken as a whole whatever shape it has: a JSON array or object is replaced in one step (`{"apiSecret":["shortpw","morepw"]}` becomes `{"apiSecret":[redacted]}`), a `Bearer`/`Basic` value of any length under a credential key keeps its scheme word, and a multi-line PEM block is replaced in one go. An unbalanced structure is cut at the end of its line rather than left readable. Redaction is idempotent, so a message that is redacted twice reads exactly as it did after the first pass.
- Redaction is bounded and cannot fail: text is cut to 64 KiB before it is scanned (and ends with `…[truncated]`), and a scan that fails for any reason returns the bare `[redacted]` instead of throwing — a broken redactor can neither turn an error path into an exception nor echo the message it was given. Every provider-registered qualifier, the escaping, and the scanner's own grammar are covered by a seeded fuzz test and linear-time checks, so a pathological message cannot make redaction expensive.
