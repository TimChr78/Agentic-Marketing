section: Security
issues: [898]
---
- Credential redaction now recognises a key by its last word, split on camelCase/PascalCase boundaries and on `_`, `-` and `.`: `authToken`, `apiSecret`, `oauthToken`, `X-Auth-Token`, `"accessToken"` and a `?apiSecret=` query parameter are redacted like `access_token` already was, while `monkey`, `keyboard`, `author`, `authority`, `tokenizer` and `sessions_count` are left alone. A credential pair nested in another value (`access token: access_token=…`) is still redacted field by field, and a message with nothing to redact is unchanged.
- For the word `key` the rule is narrower, so ordinary fields keep their text in validation and conflict messages: `key` on its own, and a compound ending in `key` whose preceding word is a credential qualifier — `api`, `secret`, `private`, `signing`, `access`, `auth`, `session`, `client`, `consumer`, `encryption`, `hmac`, `jwt`, `vault`, a provider name such as `shopify`/`twilio`, and the rest of a fixed list — are credential keys (`api_key`, `x-api-key`, `X-Auth-Key`, `aws_secret_access_key`, `signingKey`, `sessionKey`, `apiKey2`), while `entryKey`, `idempotencyKey`, `sortKey`, `primaryKey`, `cacheKey`, `foreignKey`, `keyId` and `Allowed keys` are not, so `config.entryKey: property is required …` reaches the person unchanged. An ordinary `…Key` field's value is still covered by every other rule, so a provider prefix, a JWT, a URL password or a long bare token there is redacted all the same. A qualifier-free compound a future provider invents (`tenantKey`) is the accepted cost of keeping those messages readable.
- The value of a credential key is taken as a whole whatever shape it has: a JSON array or object is replaced in one step (`{"apiSecret":["shortpw","morepw"]}` becomes `{"apiSecret":[redacted]}`), a `Bearer`/`Basic` value of any length under a credential key keeps its scheme word, and a multi-line PEM block is replaced in one go. An unbalanced structure is cut at the end of its line rather than left readable. Redaction is idempotent, so a message that is redacted twice reads exactly as it did after the first pass.
